# Recruitment App v2 — описание реализованного функционала

> Документ для презентации. Описывает то, что **уже работает в коде** на момент 5 мая 2026.
> Технические разделы и точные ссылки на файлы — в конце.

---

## 1. Что это

B2B-платформа для найма. Один заказчик = одна организация (multi-tenant). Внутри каждой организации рекрутеры:

1. Создают **позиции** (вакансии) — вручную или с помощью AI-ассистента в формате диалога.
2. Загружают **кандидатов** — резюме в PDF/DOCX, текст из буфера, JSON c HeadHunter, или принимают заявки через **публичную ссылку на вакансию**.
3. Получают **оценку соответствия** кандидата вакансии по 4 критериям с подробными комментариями (LLM).
4. Видят **обратное сопоставление** — для одного кандидата сразу понятно, к каким открытым вакансиям он подходит лучше всего.
5. Готовятся к интервью — **AI генерирует вопросы** под конкретного кандидата+вакансию, рекрутер выставляет оценки 1–5 и видит средний балл.
6. **Чатятся с AI** в контексте конкретного кандидата, конкретной вакансии или свободно (поток ответов через SSE с подсветкой markdown).

Интерфейс: тёмная тема по умолчанию, монохром + один акцент (emerald), плотная вёрстка в духе Linear / Vercel / Raycast. Двуязычный — русский (по умолчанию) и английский, переключатель в шапке.

## 2. Реализованный функционал

### 2.1. Аутентификация и роли

- Вход через email + пароль (NextAuth credentials provider, JWT 7 дней).
- Регистрация **только через админа** — публичной формы регистрации нет (B2B).
- Роли: `admin`, `recruiter`, `hiring_manager`. Бэкенд проверяет роль на каждом защищённом запросе.
- Раздел **Settings** — смена пароля, переключение языка, у админа дополнительно панель управления пользователями (создание, удаление, смена роли).

### 2.2. Multi-tenancy (изоляция организаций)

- Каждая таблица (`positions`, `candidates`, `scores`, `chat_sessions`, `messages`, `interviews`, …) имеет колонку `organization_id` с индексом.
- Все запросы фильтруются по `organization_id` пользователя из JWT — **никакая компания не видит данные другой**.
- В v1 один пользователь принадлежит одной организации (без переключения между организациями).

### 2.3. Позиции (вакансии)

- CRUD: создание, чтение, редактирование, удаление, смена статуса (`open`/`paused`/`closed`).
- **Telegram-style chips** для требований: `seniority`, `stack`, `location`, `team_size`, `salary_from`, `salary_to`, … хранятся как key-value в JSONB-поле `requirements`.
- Внутренние **заметки рекрутера** (`internal_notes`) — публично не показываются.
- Флаг `public_apply_enabled` — управление видимостью на публичной странице.
- На странице вакансии: список ранжированных кандидатов (по итоговому баллу), форма загрузки CV, встроенный чат об этой вакансии.

### 2.4. Создание вакансии через AI-диалог (`/positions/new`)

- Сплит-экран: слева чат-ассистент, справа живое превью карточки вакансии.
- Ассистент задаёт уточняющие вопросы (стек, грейд, формат работы, зарплата, размер команды), показывает **quick-reply подсказки** (кликабельные чипы).
- Принимает прикреплённые **JD-файлы** (PDF/DOCX/TXT/MD) — извлекает текст и встраивает в диалог.
- Локально хранит **множественные черновики** (localStorage) — рекрутер может вести несколько вакансий параллельно и переключаться между ними.
- Серверная часть: `POST /positions/draft` — stateless эндпоинт принимает историю сообщений + текущий черновик, возвращает следующую реплику + обновлённый JSON + флаг готовности + список недостающих обязательных полей.

### 2.5. Кандидаты — три способа добавления

| Способ | Эндпоинт | Что делает |
|---|---|---|
| Файл (PDF/DOCX) | `POST /candidates/upload/file` | Извлекает текст (pypdf, python-docx), сохраняет файл на диск, создаёт `Candidate` |
| Чистый текст | `POST /candidates/upload/text` | Принимает CV из буфера, сохраняет как `raw_cv` |
| HeadHunter JSON | `POST /candidates/upload/hh` | Парсит JSON-резюме hh.ru, синтезирует текст для скоринга, сохраняет JSON в `parsed_cv` |

Кнопка **«Добавить кандидата»** на странице `/candidates` — диалог с тремя вкладками. Кандидат добавляется **без привязки к вакансии** и попадает в общий пул — рекрутер потом сам выбирает, к каким вакансиям применить.

### 2.6. Публичная страница подачи заявки (`/apply/[id]`)

- Открывается **без авторизации** — рекрутер делится ссылкой в Telegram, на сайте, в группах.
- Кандидат заполняет: имя, телефон (обязательно), email, source (utm_source из URL), CV (файл или текст).
- **Дедупликация на лету**: бэкенд нормализует телефон (только цифры с `+`) и email (lowercase, trim) и проверяет, нет ли уже такого кандидата в этой организации. Если есть — `409 Conflict` с обтекаемым сообщением (не раскрывает, по какому полю совпало, чтобы нельзя было перебрать базу).
- После успешной подачи — фоновая задача автоматически запускает скоринг кандидата под эту вакансию.
- Поле `applied_via` сохраняется в `parsed_cv` — рекрутер видит, откуда пришла заявка (`somon`, `telegram`, `linkedin`, …).

### 2.7. AI-скоринг кандидатов

- 4 критерия с фиксированными весами (как в v1):

| Критерий | Вес |
|---|---|
| `technical_skills` (технические навыки) | 40% |
| `quality_of_projects` (качество проектов) | 30% |
| `previous_experience` (опыт) | 20% |
| `impact` (импакт / вклад) | 10% |

- Каждый критерий — целое число от 0 до 100 + развёрнутый комментарий на русском (объяснение, на чём LLM обосновывает оценку).
- Итоговый балл — взвешенное среднее.
- Уникальный ключ `(candidate_id, position_id)` — переоценка перезаписывает старую запись.
- LLM: **Google Gemini 2.5 Flash** через **OpenRouter**, температура 0.0 (детерминизм).
- **Все запросы к LLM логируются** в таблицу `messages` (модель, токены на вход/выход, назначение). Это позволяет в любой момент посчитать стоимость и сравнить разные модели.

### 2.8. Обратное сопоставление: кандидат → подходящие вакансии

- На странице кандидата панель **«Подходящие позиции»**.
- Эндпоинт `GET /candidates/{id}/best-positions` — возвращает все открытые вакансии организации, сортировка: уже оценённые сверху по убыванию балла, неоценённые снизу.
- Кнопка **«Оценить все открытые»** (`POST /candidates/{id}/score-all-open`) — пакетный скоринг по всем неоценённым вакансиям. Используется, когда новый кандидат «заехал в общий пул» и нужно понять, куда его лучше двинуть.

### 2.9. AI-чат с потоковой передачей (SSE)

Три режима (`scope`):

| Режим | Контекст, который AI видит |
|---|---|
| `candidate` | Резюме кандидата + все его оценки + сравнение с топ-15 пиров по той же вакансии |
| `position` | Описание + требования вакансии + список всех кандидатов на неё с их оценками |
| `free` | Без специфического контекста |

- Поток ответов через **Server-Sent Events** — токены отображаются по мере генерации.
- **Markdown-рендеринг** в сообщениях (заголовки, списки, код, цитаты).
- **Умная прокрутка** — страница не «выдёргивается» вниз, если пользователь читает старое сообщение.
- История чатов — на странице `/conversations`, с фильтрами по типу (кандидат / позиция / свободный).

### 2.10. Подготовка к интервью

- Эндпоинт `POST /candidates/{id}/interviews/generate` — AI генерирует N (по умолчанию 5) вопросов под конкретную пару кандидат+вакансия.
- Каждый вопрос имеет:
  - **Категорию** (`technical` / `behavioral` / `situational` / `culture`)
  - **Текст вопроса**
  - **Обоснование** — почему именно этот вопрос
  - **Ожидаемые сигналы** — на что обращать внимание в ответе
- Рекрутер выставляет **оценку 1–5 по рубрике** для каждого вопроса + свои заметки.
- Итоговый балл интервью — среднее по выставленным оценкам.
- Статусы: `draft` → `in_progress` → `scored` → `archived`.

### 2.11. Интернационализация

- Языки: `ru` (по умолчанию) и `en`.
- Переключатель — в шапке (cookie `locale` на 365 дней).
- У каждого пользователя свой `locale` в БД — синхронизируется при логине.
- Все строки UI типизированы (`Messages` тип) — **компилятор гарантирует**, что не пропущен ни один перевод.

### 2.12. Логирование LLM-вызовов

Каждый вызов LLM (скоринг, чат, генерация вопросов, драфт вакансии) пишет **2 строки** в таблицу `messages`:
- Промпт пользователя (`role=user`)
- Ответ модели (`role=assistant`) с `model_used`, `tokens_in`, `tokens_out`, `purpose`.

Поле `purpose` различает `chat` / `scoring` / `interview` / `position_draft` — позволяет агрегировать стоимость и время по каждому типу операций.

## 3. Архитектура (4 слоя)

```
┌─────────────────────────────────────────────────────┐
│  UI Layer  — Next.js 16 (App Router, RSC)           │
│  Server Components для чтения, Server Actions       │
│  для мутаций. Не знает ничего про LLM и движок.     │
└────────────────────┬────────────────────────────────┘
                     │ HTTPS + JWT в Authorization
┌────────────────────▼────────────────────────────────┐
│  API Layer — FastAPI (async)                        │
│  Auth, позиции, кандидаты, оценки, чат, интервью.   │
│  Multi-tenancy через organization_id на каждой      │
│  таблице.                                           │
└──────┬───────────────────────────────────┬──────────┘
       │                                   │
┌──────▼─────────────┐          ┌──────────▼─────────┐
│  Engine Layer      │          │  LLM Layer         │
│  Скоринг, чат,     │          │  Абстракция        │
│  драфт вакансий,   │──────────▶  LLMClient.        │
│  генерация         │          │  Адаптер           │
│  интервью.         │          │  OpenRouter (gemini│
│  Промпты           │          │  -2.5-flash);      │
│  и schema от v1.   │          │  vLLM — стаб.      │
└────────────────────┘          └────────────────────┘
```

**Принципы:**
1. **`ScoringEngine` — единственная точка входа** для оценки. UI и API не знают про внутренности (промпты, формат JSON, веса).
2. **`LLMClient` — единственная абстракция LLM.** Смена провайдера — изменение одной env-переменной. Все вызовы автоматически логируются.
3. **Чат — самостоятельный bounded context.** Сессии чата ссылаются на кандидатов и вакансии, но живут отдельной таблицей. Это ключевая архитектурная развязка по сравнению с v1.
4. **Всё, что пишет в БД, идёт через server actions** на фронте. Ни один компонент не делает мутаций фетчем напрямую.

## 4. Стек (точные версии)

### Frontend (`apps/web`)

- **Next.js 16.2.4** — App Router, Server Components, Server Actions, middleware
- **React 19.2.4**
- **NextAuth 5.0.0-beta** (Auth.js) — credentials provider, JWT strategy
- **Tailwind CSS v4** — токены через CSS-переменные
- **shadcn/ui** на базе **`@base-ui/react`** (заменил Radix в актуальной shadcn)
- **react-hook-form 7.75 + zod 4.4** — формы с валидацией
- **sonner 2.0** — тосты, **lucide-react** — иконки, **next-themes** — переключение темы

### Backend (`apps/api`)

- **FastAPI 0.136** + **uvicorn 0.46**
- **Python ≥ 3.12**
- **SQLAlchemy 2.0** (async) + **asyncpg 0.31** + **alembic 1.18**
- **python-jose 3.5** (JWT, HS256) + **bcrypt 5.0** (хэширование паролей)
- **openai 2.33 SDK** (с `base_url=https://openrouter.ai/api/v1` для OpenRouter)
- **pypdf 6.10** + **python-docx 1.2** — извлечение текста из CV

### Инфраструктура

- **PostgreSQL 16** (Docker, Alpine-образ, dev-compose в репо)
- **OpenRouter** как primary LLM-провайдер, default model `google/gemini-2.5-flash`
- **Файловое хранилище** — локальный диск (`./storage/cvs/<uuid>.pdf`), S3/Supabase Storage планируется на деплое

## 5. Модель данных (8 таблиц)

```
organizations    id, name, slug, created_at
       │
       │ (1:N)
       ▼
users            id, organization_id, email (unique), password_hash,
                 role (admin|recruiter|hiring_manager), locale (ru|en)

positions        id, organization_id, title, description,
                 requirements (jsonb), internal_notes,
                 status (open|paused|closed), public_apply_enabled,
                 created_by, created_at, updated_at

candidates       id, organization_id, source (manual|hh|public),
                 source_ref, raw_cv (text), parsed_cv (jsonb),
                 pdf_path, phone_normalized (idx), email_normalized (idx),
                 is_favorite, viewed_at, created_at

scores           id, organization_id, candidate_id, position_id,
                 score_technical_skills, score_quality_of_projects,
                 score_previous_experience, score_impact (все 0..100),
                 comment_* (4 шт., текст),
                 overall_score, overall_recommendation,
                 model_used, scored_at
                 UNIQUE (candidate_id, position_id)

chat_sessions    id, organization_id, user_id,
                 scope (candidate|position|free),
                 candidate_id (nullable), position_id (nullable),
                 title, created_at, updated_at

messages         id, organization_id, session_id (nullable),
                 role (user|assistant), content,
                 model_used, tokens_in, tokens_out,
                 purpose (chat|scoring|interview|position_draft),
                 created_at

interviews       id, organization_id, candidate_id, position_id,
                 status (draft|in_progress|scored|archived),
                 notes, overall_score, model_used, created_by

interview_questions  id, organization_id, interview_id (cascade),
                     position (порядок), category, question_text,
                     rationale, expected_signals,
                     score (1..5, nullable), notes
```

## 6. Что хорошо отрабатывает в демо

- Полная цепочка: создал вакансию → дал публичную ссылку → кандидат подал заявку через `/apply/[id]` → автоматический скоринг → рекрутер видит кандидата с готовой оценкой и комментариями → запускает чат с AI про этого кандидата → генерирует интервью → выставляет оценки.
- Дубли реально отсекаются (нормализация телефона/email).
- Один кандидат — много вакансий: можно одной кнопкой проскорить по всем открытым позициям и увидеть, куда он лучше встанет.
- Чат отвечает по существу — он видит CV, оценки, и сравнивает с другими кандидатами.

## 7. Что отложено (не блокирует демо)

- Деплой в Vercel + Railway (сейчас всё локально, но запускается одной командой, см. раздел Local development в `README.md`).
- vLLM-адаптер (стаб готов, переключение по env-переменной).
- HH.ru OAuth (сейчас только paste JSON вручную).
- Email/SMS/Telegram нотификации.
- Пагинация (на размере одной организации с сотнями кандидатов и десятками вакансий — не нужна).
- Полнотекстовый поиск, расширенные фильтры по диапазонам оценок.
- Soft-delete / аудит-лог.
