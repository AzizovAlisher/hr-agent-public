# Pilot Defect Ledger

This is the closure ledger for the current E18 private-pilot candidate. A defect is
`closed` only after a regression test and an independent adjacent-flow retest.
Live provider certification and customer acceptance are release approvals, not
software defects, and are recorded separately below. Closed E14 rows remain
historical evidence; current-pilot release status is recorded after the table.

## Closure-record composition

The summary row below and its keyed entry in
[`evidence/defect-closure-index-e18.json`](./evidence/defect-closure-index-e18.json)
together form the complete defect record required by the acceptance protocol.
The index has exact ID parity with this table and hash-binds every row to its
area, severity, status, owner, implementation commit, resolved
tenant/role/locale/device/environment context, current-tree regression
locators, exact independent-retest text, adjacent-flow disposition, and evidence
paths. Shared contexts remove repetition without requiring reviewer inference.
The validator rejects missing or extra IDs/fields, unknown commits/contexts,
missing locator/evidence files, ledger-field or row-hash drift, and a `closed`
row without a passed adjacent disposition. It is a structural traceability
check only: it cannot prove execution, supply independent verification, or
authorize a release. Immutable hosted artifacts and external reviewer
attestations supply that evidence. `DEF-055`, `DEF-062`, and `DEF-063` remain explicitly
`verification`/`pending_hosted` until the corrected immutable revision passes
their hosted gates.
